# 02 观象资料整理

## 1. 观象的产品定位

“观象”在 Vina 中建议定义为“确认与展示卦象结构”的阶段，而不是最终断语阶段。

用户起卦后先看到卦象预览，确认“问题、时间、六爻、动爻、本卦、变卦”无误，再进入完整排盘和解卦。这与现有功能规划中“自动起卦后先返回预览对象，用户确认后才继续排盘和解卦”的设计一致。

## 2. 基础展示信息

观象阶段展示以下结构：

| 信息 | 说明 |
|---|---|
| 本卦 | 起卦所得六爻组成的卦 |
| 变卦 | 动爻反转后形成的卦；无动爻时可显示“无变”或同本卦 |
| 动爻 | 老阴、老阳所在爻位 |
| 上卦/下卦 | 上三爻为外卦，下三爻为内卦 |
| 爻位 | 初、二、三、四、五、上 |
| 阴阳 | 阳爻、阴爻 |
| 起卦时间 | 用于后续月建、日辰、六神、空亡等计算 |
| 问题类型 | 用于后续取用神 |

## 3. 爻位与上下卦

六爻从下往上排列：

- 初爻：最下方，第 1 爻。
- 二爻：第 2 爻。
- 三爻：第 3 爻。
- 四爻：第 4 爻。
- 五爻：第 5 爻。
- 上爻：最上方，第 6 爻。

下三爻组合为下卦，上三爻组合为上卦。六十四卦由上卦与下卦组合而成。

## 4. 动爻观象

动爻是观象阶段最重要的交互信号：

- 老阴动：本卦为阴，变卦为阳。
- 老阳动：本卦为阳，变卦为阴。
- 多个动爻：全部反转生成变卦。
- 无动爻：变卦与本卦一致，解卦时应以静卦逻辑处理。

UI 建议：

- 在六爻图上用圆点、闪光、侧标或动爻符号标识动爻。
- 本卦和变卦并列展示，动爻用连线说明变化。
- 不在观象阶段输出强烈吉凶判断，避免用户跳过完整解卦依据。

## 5. 完整排盘字段

用户确认卦象后，观象信息应扩展为排盘：

| 字段 | 用途 |
|---|---|
| 六亲 | 取用神、判断主体关系 |
| 六神 | 补充象意，不作为单独吉凶依据 |
| 世应 | 世爻代表求测者/自身，应爻代表对方/对象/外部响应 |
| 干支五行 | 判断生克、冲合、旺衰 |
| 月建 | 判断当月旺衰、月破等 |
| 日辰 | 判断日上生克、冲合、旬空、六神起排 |
| 旬空 | 判断暂空、落空、待填实 |
| 变爻 | 分析事情变化方向 |

## 6. 观象输出对象建议

```ts
interface HexagramPreview {
  question: string;
  topic: "career" | "wealth" | "relationship" | "health" | "general";
  castTime: string;
  lines: CastLine[];
  primaryHexagram: HexagramRef;
  changedHexagram: HexagramRef | null;
  movingLines: number[];
}

interface HexagramRef {
  name: string;
  upperTrigram: string;
  lowerTrigram: string;
  binary: string;
}
```

`binary` 建议按初爻到上爻记录，例如阳为 `1`、阴为 `0`，方便计算上下卦。
